| HIGH | `src-tauri/src/sftp/mod.rs:882` | Remote rename target collision is destructive: `rename_via` does best-effort `remove_file(to)` before `rename`. ## Task 2 - File Split Planning

`src-tauri/src/sync/auto_sync.rs` should split around engine orchestration vs workers. Keep public types, `AutoSyncEngine` struct, lifecycle (`start_with`, `stop`, status, watch management), and command-facing methods in `auto_sync.rs` or `sync/auto_sync/mod.rs`. Move notify ingestion/debounce queue into `sync/auto_sync/watch.rs`, flush/process/upload/delete handling into `sync/auto_sync/flush.rs`, drift reconcile kick + helper accessors into `sync/auto_sync/drift.rs` only if it reduces coupling w/ existing `drift_watcher.rs`, and pure helpers/tests (`map_local_to_remote`, `safe_count_files`, `classify_action`) into `sync/auto_sync/path.rs` / `tests.rs`. Public API impact should be near zero: keep `pub use` surface from `sync::auto_sync` unchanged; internal modules can use `pub(super)` helpers.

`src-tauri/src/sftp/mod.rs` should split by transport/session vs file operations. Keep `ConnectArgs`, `SftpClient`, worker pool/session open/close, `RemoteEntry`, `RemoteFileInfo`, and `OpResult` in `sftp/mod.rs`. Move listing/batch listing to `sftp/list.rs`, upload/download atomic + batch transfer to `sftp/transfer.rs`, path ops (`rename`, `delete`, `delete_recursive`, `mkdir_p`, `remote_parent`) to `sftp/ops.rs`, and shell-backed helpers (`get_remote_sha1`, folder size, `shell_quote`) to `sftp/remote_exec.rs`. Public API impact should be none if `impl SftpClient` blocks live in submodules and `mod.rs` re-exports only the existing types.
