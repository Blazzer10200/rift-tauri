# Sync Layer Audit — 2026-05-11

Files audited: `auto_sync.rs` (1483L), `drift_watcher.rs` (381L), `drift_scanner.rs` (397L),
`lock_presence.rs` (261L), `edit_trail.rs` (129L), `ignore.rs` (290L),
`state/sync_snapshot.rs` (334L), `state/remote_state.rs` (129L).

Duplicates from `codex-2026-05-11.md` excluded.

| Severity | File:line | Issue | Suggested fix |
|---|---:|---|---|
| HIGH | `auto_sync.rs:869` | Lock fire-and-forget spawns on EVERY `queue_path` call for the same path. Debounce `and_modify` updates the dirty entry but does not gate the lock-acquire spawn. Rapid edits produce multiple overlapping `acquire` tasks for the same remote path. | Guard spawn with a check against `LockPresence::my_locks` (already exposed) before spawning. Skip if lock is already held for that remote path. |
| HIGH | `auto_sync.rs:1141` | Requeue after `wait_for_readable` failure clones `entry` and inserts with `attempts: 0` reset. A permanently unreadable file (antivirus lock, ACL) loops forever without hitting `mark_failed` or backoff. | Preserve and increment `attempts` on readable-wait requeue; call `mark_failed` after exceeding a threshold (e.g. 4 readable-wait failures). |
| HIGH | `auto_sync.rs:1146` | Second existence check after `wait_for_readable` success also requeues with `attempts: 0` if file vanished. Vanished file after a readable-wait is functionally "deleted" — requeueing resets the counter. | Treat vanished-after-readable-wait as `EntryResult::Ok` (file gone = effectively synced) or `mark_failed`; never requeue with reset count. |
| HIGH | `drift_watcher.rs:310` | `pull_one` calls `remote_stat` after download inside the `if dirty` block but never checks `info.exists`. A failed stat returns default zeros; the `ConflictRecord` is seeded with `remote_size=0, remote_mtime=epoch`. | Check `info.exists` before building the `ConflictRecord`; fall back to local metadata for size/mtime when stat is unavailable. |
| HIGH | `lock_presence.rs:219` | `poll_once` calls `active_by_path.clear()` then re-populates in a for-loop. Concurrent `find_lock_by_other` calls during the clear→re-insert window see an empty map and return `None`, allowing blocked uploads to proceed through the lock check for one full re-insert cycle. | Build a replacement map, then do per-key `insert`/`remove` to avoid the empty-window. Or swap under a single-writer lock. |
| HIGH | `drift_scanner.rs:286` | First-scan branch (`l.is_some() && r.is_some() && snap.is_none()`) falls through to `DriftBucket::Conflict` when sizes differ. There is no prior agreement — no baseline to conflict against. Every fresh connect where local and remote diverged before Rift was installed produces a spurious Conflict instead of a directional pull/push. | First-scan size mismatch should produce `ToPull` or `ToPush` based on relative mtime (newer side wins), not `Conflict`. Reserve `Conflict` for cases with an existing baseline. |
| HIGH | `sync_snapshot.rs:117` | `save()` releases the mutex lock before serializing + writing to disk. Two concurrent `set()` calls can both clone the map, race to serialize, and the later writer silently overwrites the earlier. If the process crashes between the two writes, one entry is lost from disk (but remains in memory). | Serialize inside the lock, or funnel disk writes through a single-writer background task/channel. |
| MED | `auto_sync.rs:953` | `flush_batch` awaits `safe_count_files` inline on every flush cycle that has delete entries. Under a large resource folder this blocks the flush task for the duration of the blocking walk even though `spawn_blocking` offloads I/O — the `await` stalls `flush_cycle` until the count returns. | Cache the file count per `FolderWatch` (refresh on watch add/remove + e.g. every N minutes). Avoid re-walking on every batch with deletes. |
| MED | `auto_sync.rs:1302` | `mark_failed` logs "giving up" when `attempts > RETRY_BACKOFFS_SECS.len()` but still inserts into `failed` with a 600s next_retry. The entry grows the `failed` DashMap indefinitely; `flush_cycle` skips it via the promote guard but never removes it. Accumulates stale entries across long sessions. | After logging "giving up", return without inserting into `failed`. Optionally track in a separate permanent-failed set for UI display. |
| MED | `edit_trail.rs:75` | `read_raw` creates a subdirectory in `temp_dir` (`rift-trail-{pid}-{short_id}`) and removes it with `remove_dir_all`. If two concurrent `append` calls race with the same PID+short_id (short_id entropy is low under rapid calls), one call may delete the other's downloaded file mid-read. | Use a uniquely named file directly in `temp_dir` (no subdirectory), or use `tempfile::NamedTempFile` for guaranteed uniqueness. |
| MED | `drift_scanner.rs:163` | `rel` derived via raw byte-index slice `r.full_path[rr_len..]`. `rr_len` is the byte length of the trimmed `remote_root` string. A remote path containing multi-byte UTF-8 characters will panic if `rr_len` does not align to a char boundary. | Use `full_path.get(rr_len..).unwrap_or(&full_path)` or `full_path.strip_prefix(trimmed_root)`. |
| MED | `drift_watcher.rs:56` | After `is_pushing` skip, the loop re-sleeps the full `secs` interval rather than a shorter retry. A push storm at second 29 of a 30s interval causes a full additional 30s delay before the next pull check — effectively doubling pull detection latency during heavy upload activity. | After a pushing-skip, sleep a short retry interval (e.g. 5s) so pulls are picked up promptly once the push drains. |
| MED | `ignore.rs:163` | `_disabled_archive` is in `IGNORE_SEGMENTS` but has no explicit arm in the `match *seg` block — falls through to `"seg:?"`. All other segments have stable labels. | Add `"_disabled_archive" => "seg:_disabled_archive"` to the match arm. |
| LOW | `auto_sync.rs:444` | `try_watch` ignore probe builds path via `format!("{}{}", local_root.display(), MAIN_SEPARATOR)`. On Windows, `display()` uses backslashes; `MAIN_SEPARATOR` = `\`. Normalization inside `classify` papers over this, but the probe string is fragile and inconsistent with how all other callers build paths for `should_ignore`. | Use `local_root.to_string_lossy().replace('\\', "/")` to build the probe, consistent w/ rest of the codebase. |
| LOW | `auto_sync.rs:818` | `is_dir` check follows symlinks (`path.is_dir()`). A symlink to a directory inside the watch root is silently skipped — its children are never queued. No diagnostic is emitted. | Log the skipped symlinked-dir case at debug level so it appears in the Diagnostics panel. |
| LOW | `sync_snapshot.rs:105` | `compute_sha1` calls `std::fs::read(local_path)` — reads entire file into a heap buffer. Up to 25 concurrent scanner calls per folder × up to 64 MiB each = up to 1.6 GiB peak allocation under a full budget sweep. | Stream SHA1 via `BufReader` (8 KiB chunks) to avoid large concurrent allocations. |
| LOW | `edit_trail.rs:88` | `trim_to_tail` splits on `'\n'`. JSONL fetched from a Windows-line-ending SFTP server may contain `\r\n`; `split('\n')` leaves `\r` in each line. `join("\n")` re-inserts `\r` mid-line, producing invalid JSON on the next read cycle. | Strip `\r` from each line after split, or use `.lines()` which handles both `\n` and `\r\n`. |
| LOW | `lock_presence.rs:197` | Stale-lock delete failures are silently swallowed. If the delete fails, the lock file persists and triggers another delete attempt every 10s indefinitely with no log output. | Log a warning on stale-lock delete failure; consider a per-path attempt counter with backoff. |
