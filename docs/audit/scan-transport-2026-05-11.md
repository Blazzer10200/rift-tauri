## Findings

| Severity | File:line | Issue | Suggested fix |
|---|---|---|---|
| HIGH | `src-tauri/src/transport/ssh_handler.rs:49` | Fingerprint pin uses `.contains(bare)` — bare b64 of key A is a substring of a longer b64 string that could represent key B. If a stored trusted_fingerprint is ever a padded or concatenated string that happens to contain a shorter b64 matching a rogue server's key, the rogue is accepted. More concretely, the "WPF format" path `"ssh-ed25519 256 SHA256:<b64>"` is checked by extracting the bare b64 and calling `trusted.contains(bare)` — any stored fp string that contains that b64 as a substring passes. A stored fp of `"SHA256:AAABBB"` also accepts a server whose fingerprint bare b64 is `"AAA"`. | Replace substring match with exact equality: strip `SHA256:` from both computed fp and stored fp, then compare the resulting bare b64 strings for equality. Accept the three stored formats by normalizing both sides before comparison rather than substring. |
| HIGH | `src-tauri/src/sftp/mod.rs:229` | `ensure_workers` holds `self.workers.lock()` (line 229) while driving `open_futs.next().await` in a loop. Each `next()` awaits a network round-trip (SSH kex + auth). Any other task that calls `workers.lock()` during this window blocks for the full handshake duration. With 4 workers × ~150ms each = up to 600ms of lock contention. Callers include `live_worker_count`, `download_files_batch`, `upload_files_batch`, `list_recursive_batch` — all stall on this path. | Collect opened sessions into a local `Vec<Worker>` outside the lock; acquire `workers` once only to extend. The `worker_open_lock` already serializes concurrent `ensure_workers` calls; the inner `workers` lock only needs to be held for the final append. |
| MED | `src-tauri/src/sftp/mod.rs:880` | `delete_recursive_via` child guard: `ft.is_dir() && !ft.is_symlink()`. `russh_sftp::protocol::FileType` is an enum, not `std::fs::FileType`; `is_symlink()` may not be defined on it or may always return false depending on the crate version. If the method is absent or incorrect, symlinked subdirs are treated as real dirs and recursed into, escaping the containment boundary. | Explicitly match `FileType::Symlink` variant in the branch condition rather than relying on an `is_symlink()` method; add a compile-time test that `FileType::Symlink` exists and routes to `remove_file`. |
| MED | `src-tauri/src/sftp/mod.rs:726` | `get_remote_sha1`: path is passed through `shell_quote` which does not strip NUL bytes or newline characters (documented in the fn comment at line 1030). A remote path containing `\n` injects a second shell command after `sha1sum`, executed in the same `exec` channel. SFTP paths technically permit newlines; FXServer hosts don't use them in practice, but the boundary is caller-controlled. | Add NUL + newline rejection to `shell_quote` (or to both call sites). A 2-line guard: `if s.contains(['\0', '\n', '\r']) { return Err/panic }` before the quote loop. |
| MED | `src-tauri/src/sftp/mod.rs:462` | `get_remote_folder_size`: same shell-injection via newline in `remote_path` — `shell_quote(remote_path)` is embedded in a `find …` command string passed to `exec`. Same root cause as the sha1sum call above. | Same fix: reject newline + NUL in `shell_quote`. |
| MED | `src-tauri/src/sftp/mod.rs:351` | Worker batch listing false-empty bypass: line 351 uses `.unwrap_or_default()` on `list_recursive_via(…).await`, converting `Err` (mid-walk session failure) into `Ok(vec![])`, which then inserts the key into `results_arc`. The belt-and-braces retry on lines 367-382 only fires when the key is **absent** from the map. A worker that breaks mid-walk silently inserts an empty vec → retry never runs → false-empty propagates to drift scan as if the folder is genuinely empty → false push regression. | Return `Result<Vec<_>>` from the worker task path; only insert into `results_arc` on `Ok`; on `Err`, skip the insert so the retry loop catches it. |
| MED | `src-tauri/src/tunnel/mod.rs:117` | Per-connection tasks are `tokio::spawn`-ed and outlive `SshTunnel::stop()`. `stop()` only awaits the accept loop task, not the per-conn tasks. If a `copy_bidirectional` stalls (server hangs, half-open TCP), the per-conn task holds an `Arc<Handle>` clone indefinitely → SSH session never fully tears down. Autosync stop that calls `SshTunnel::stop()` returns immediately but the SSH connection lingers. | Pass a `CancellationToken` into each per-conn task; `select!` between `copy_bidirectional` and the cancel signal. Cancel all per-conn tokens in `stop()` before returning, or add a per-conn timeout. |
| MED | `src-tauri/src/edit/in_place.rs:100` | `begin_edit` accepts any `remote_path` without validating containment under the server's configured `remote_root`. A crafted path like `../../etc/passwd` downloads to `tmp_root/<subdir>/passwd` (local write is contained — filename is extracted from last `/`), but the same path is then used in `save()` → `upload_file_atomic` → writes back to `../../etc/passwd` on the remote. The upload path has no containment guard at the SFTP layer. | Validate `remote_path` against the server profile's `remote_root` in both `begin_edit` and `save()`, using the same containment helper planned for lib.rs command handlers. |
| LOW | `src-tauri/src/sftp/mod.rs:247` | `SftpClient::close` holds `self.workers` lock while awaiting `w.sftp.close()` for each worker. If a close call stalls (network), the lock is held for the duration, blocking any concurrent access to the worker pool. Not a liveness issue at shutdown, but if `close` is called from a context where other tasks may still be referencing the pool, the stall is observable. | Collect `Arc<Worker>` clones, drop the lock, then close sequentially (or concurrently with `join_all`) outside the lock. |
| LOW | `src-tauri/src/update_service.rs:110` | `RIFT_UPDATE_FEED` local FileSource bypass is not gated by build profile. In a release build, a local process or user with env access can set this variable to a crafted feed directory and trigger Velopack to apply a malicious update package. Dev-only by convention but not enforced. | Add `#[cfg(debug_assertions)]` guard around the `RIFT_UPDATE_FEED` branch, or require an explicit signed marker file in the directory. |
| LOW | `src-tauri/src/edit/in_place.rs:287` | `Drop` for `EditInPlaceManager` calls `std::fs::remove_dir_all(&self.tmp_root)` synchronously. If called from an async context (e.g. when the manager is held in a `tokio::sync::Mutex` that gets dropped), this blocks the async thread for the filesystem I/O duration. With many large edit-session tmp files this is observable latency. | Use `tokio::task::spawn_blocking` for the cleanup, or add an explicit `async fn close_all()` called before drop. |
| LOW | `src-tauri/src/transport/ssh_keygen.rs:75` | `SshKeygen::generate` writes the private key file with no explicit permissions set. On POSIX hosts (non-Windows), the file inherits the process umask, typically `0644` — world-readable. The comment says "caller is responsible for chmod" but no caller currently sets it. | After the `fs::write` call, on `#[cfg(unix)]` set file permissions to `0o600` using `std::fs::set_permissions`. |
| LOW | `src-tauri/src/edit/in_place.rs:126` | `short_id()` generates a 32-bit (4-byte) random subdir name. With concurrent edit sessions and many opens over a session lifetime, the birthday collision probability is non-negligible at scale (~1/42M per pair). Not exploitable, but two simultaneous `begin_edit` calls for different remote paths to the same short_id subdir would silently overwrite each other's downloaded file. | Bump `short_id()` to 8 bytes (16 hex chars) or use `uuid::Uuid::new_v4()`. |
| INFO | `src-tauri/src/bridge/mod.rs:57` | Token value is sent in an HTTP header (`X-Rift-Token`) in plaintext over HTTP (not HTTPS) to `127.0.0.1`. This is intended (tunnel scenario), but any local process can sniff loopback traffic on Windows and extract the token. Token is not logged anywhere — confirmed. | Accepted risk for loopback; document. |
| INFO | `src-tauri/src/transport/env.rs:17` | `hostname()` falls back to spawning an external `hostname` binary on non-Windows. On a system with a corrupted `$PATH`, an attacker-controlled `hostname` binary could be executed. Ambient risk only; no input from untrusted sources reaches this call. | Document the PATH dependency. Low priority. |
