## v0.20.4 — 2026-06-17 — Claude Design integration (DesignSync surfacing)

> **Why.** Claude's new Design feature ships a `DesignSync` tool + `/design-sync` skill in the CLI that keeps a local component library in sync with a claude.ai/design project. Rift spawns that CLI, so the capability is one allowlist entry away — but the tool was denied by Rift's `--allowed-tools` gate, and any call would have rendered as a bare, unstyled chip.

**Added:**
- **`DesignSync` admitted through the CLI allowlist** (`turn.rs` `BUILTINS`). Kept out of the auto-approve set so its cloud writes ride the permission prompt; the workspace root is handed to the tool as `localDir` for free (the CLI spawn cwd). OAuth-path only — it has no auth under `--bare`/local-LLM.
- **Method-aware tool chips** for DesignSync — `write_files · N files`, `finalize_plan · N writes`, `create_project · <name>`, `get_file · <name>`, `register_assets · N cards`; the publishing methods take the write tint so a cloud upload reads as consequential at a glance.

**Verify.** version lockstep ×3 + `Cargo.lock` · `cargo check` clean · svelte-check 0/0. Live-probed in a dev session — the spawned CLI exposes `DesignSync` (as a ToolSearch-deferred tool, no denial); the full `/design-sync` round-trip needs an authed claude.ai design login, so it's exercised in prod.
