## v0.20.3 — 2026-06-17 — Effort-tier clamping + model-fallback correctness

> **Why.** The effort slider only *hid* out-of-range stops — it never coerced the stored tier — so a workspace pinned to Opus@`ultra`, then switched to Sonnet, kept sending `--effort xhigh` + `{"ultracode":true}` (both Opus-tier only) while the UI showed "Smart". Separately the Fable-unavailable fallback diverged: the backend ran Opus while the frontend showed Sonnet.

**Fixed:**
- **Effort now clamps to each model's capability ceiling**, front and back. Sonnet caps at `smart` (high); `xhigh`/ultracode are Opus-tier only. The stored pref coerces on model switch *and* workspace load, so the slider and the tier actually sent can never disagree. `turn.rs` is the authoritative gate — even a stale tier from any client is clamped before the CLI args are built.
- **Fable fallback aligned** — an unavailable/disabled Fable session now falls to **Opus** on both sides (was Opus backend / Sonnet frontend, so the app ran one model while showing another).
- **Unknown effort tier** is now validated + logged instead of silently mapping to `high`.

**Changed (lockstep debt):**
- Capability ceiling centralized: frontend `MODEL_OPTIONS.maxEffort` now derives from one `MODEL_MAX_EFFORT` map; backend grows shared `config.rs` helpers (`DEFAULT_MODEL`, `FABLE_FALLBACK_MODEL`, `EFFORT_ORDER`, `model_max_effort`, `clamp_effort`) replacing scattered hard-coded literals + a one-off Sonnet special-case.

**Verify.** version lockstep ×3 + `Cargo.lock` · svelte-check 0/0 · vitest 15/15 (helpers) · cargo test `assistant::config` 6/6 — new Rust clamp/fallback contract net mirrors the vitest so cross-boundary drift surfaces in review. Backend `cargo check` clean.
