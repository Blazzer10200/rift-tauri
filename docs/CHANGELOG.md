## v0.4.34 — 2026-05-27 — updater system overhaul: drop tauri-plugin-updater, GH-release-API path

> **Why this release exists.** `tauri-plugin-updater`'s ed25519 signature check cannot be disabled per its own docs. Lose the signing key → every installed client is bricked forever. That exact failure mode hit on v0.4.33 (encrypted key, lost passphrase, forced rotation, buddy needs manual reinstall). The plugin's design is hostile to small projects: it's a single-point-of-failure with no recovery path. v0.4.34 rips it out and replaces it with a stupid-simple GitHub Releases API check + browser-launches-Setup.exe flow. No signing key, no `latest.json`, no `*.sig` files, no plugin runtime dependency, no CONIN$ passphrase trap. The release pipeline that broke us yesterday becomes unnecessary infrastructure.

**Backend rewire.** [src-tauri/src/commands/update.rs](src-tauri/src/commands/update.rs) rewritten: single `check_for_updates` async command hits `https://api.github.com/repos/Blazzer10200/rift-releases/releases/latest`, semver-compares `tag_name` against `CARGO_PKG_VERSION`, returns a `UpdateInfoDto` with the Setup.exe `download_url`/`size_bytes`/`release_url`/`notes_markdown`/`published_at` populated from the asset listing. Network/HTTP/parse failures log + swallow (returns `None` so the UI banner stays hidden). New inline `parse_version` + `is_newer` handle `0.4.X` core + optional `-prerelease` tail, with five unit tests (`cargo test commands::update` — patch/minor/major bumps, double-digit patch ordering, release > prerelease, `v`-prefix stripping, malformed → false). User-agent set so GitHub doesn't 403. [src-tauri/src/lib.rs](src-tauri/src/lib.rs): dropped `tauri_plugin_updater::Builder::new().build()` + `tauri_plugin_process::init()` plugin registrations, dropped `PendingUpdate` managed state, removed `download_update` + `apply_pending_update` from `invoke_handler!` (the GH-release path has no staged-download or apply step — the browser handles both). [src-tauri/Cargo.toml](src-tauri/Cargo.toml): removed `tauri-plugin-updater` + `tauri-plugin-process`; added `json` feature to `reqwest` (needed for `resp.json::<GhRelease>()`). [src-tauri/capabilities/default.json](src-tauri/capabilities/default.json): dropped `updater:default` + `process:default` permissions (orphaned w/ plugins removed; would fail capability validation). [src-tauri/tauri.conf.json](src-tauri/tauri.conf.json): dropped the `plugins.updater` block (pubkey, endpoints, install-mode); kept `createUpdaterArtifacts: true` as a one-time bridge so v0.4.34's `release.ps1` still emits `*.sig` + `latest.json` and v0.4.33 clients can auto-pull this release via their old plugin path. Drop in v0.4.35.

**Frontend rewire.** [src/lib/state/updates.svelte.ts](src/lib/state/updates.svelte.ts) rewritten: state machine trimmed to `idle → checking → available → launched / uptodate / error` (dropped `downloading` + `ready` + `applying` — they no longer apply since the browser owns the download + install). `download()` calls `openUrl(info.downloadUrl)` via `@tauri-apps/plugin-opener` (already a dep), transitions to `launched`. Public store API preserved (`refresh`, `applyNow`, `snooze`, `checkOnLaunch`, `dismissToast`, `pillVisible`, `sizeLabel`, `publishedLabel`, `dispose`, `open`/`close`, `state`/`info`/`error`/`progress`/`currentVersion`/`toastVisible`/`dialogOpen`/`dismissedVersion`) so every consumer ([UpdateDialog.svelte](src/lib/components/dialogs/UpdateDialog.svelte), [UpdateToast.svelte](src/lib/components/UpdateToast.svelte), [StatusBar.svelte](src/lib/components/shell/StatusBar.svelte), [Settings.svelte](src/lib/components/settings/Settings.svelte), [AppShell.svelte](src/lib/components/AppShell.svelte)) is untouched — the rewire is invisible to them. `progress` retained as a no-op `$state(0)` for back-compat; `dispose()` is a no-op (no Tauri event listeners to tear down anymore). [UpdateDialog.svelte](src/lib/components/dialogs/UpdateDialog.svelte) trimmed: dropped progress-card + ready-card + applying branches and their CSS, added `launched` state with a "Setup.exe is downloading in your browser" card explaining the next step. Footer for `available`: snooze + "Download installer" button (opens browser). Footer for `launched`: close button. `Escape` no longer needs to be blocked mid-flight since there's no in-app download to interrupt. [package.json](package.json): dropped `@tauri-apps/plugin-updater` + `@tauri-apps/plugin-process` (`npm install` reconciled).

**v0.4.33 → v0.4.34 bridge.** v0.4.34's `release.ps1` is unchanged from v0.4.33 — it still produces `Rift_0.4.34_x64-setup.exe` + `.sig` + `latest.json` because `createUpdaterArtifacts: true` is still set. v0.4.33 clients (still running the old `tauri-plugin-updater`) will poll `latest.json` on next launch and auto-pull v0.4.34 via the OLD path. v0.4.34's binary itself uses the NEW GH-release-API path going forward — so v0.4.34 → v0.4.35 won't need any signing infrastructure. **If the bundler can't produce `.sig` without the plugin in deps**, `release.ps1` bails LOUD at the "Signature file missing" preflight check — fallback is to drop `createUpdaterArtifacts` and ship v0.4.34 as a manual reinstall for v0.4.33 clients (buddy already did exactly this for v0.4.32 → v0.4.33, no new pain).

**Post-v0.4.34 cleanup queued for v0.4.35.** Drop `createUpdaterArtifacts: true` from `tauri.conf.json`. Gut `release.ps1` to ~40 lines (just `npm run tauri build` + `gh release create $tag *-setup.exe`). Delete `~/.tauri/rift.key` + backups (no longer needed; ed25519 signing is gone). Retire `scripts/release-bridge.ps1` (already spent from v0.4.32 ship). The `assistant::kill_child_processes_on_exit` helper in [src-tauri/src/assistant/mod.rs](src-tauri/src/assistant/mod.rs) becomes an orphan (was only called from `on_before_exit` in the deleted update path) — left in place for now since it's a `pub fn` and removing it is scope creep beyond the updater task.

**Verify.** `npm run check` 0 errors / 0 warnings. `cargo check --manifest-path src-tauri/Cargo.toml` clean. `cargo test commands::update` — 5 / 5 pass (newer_patch_minor_major, double_digit_patch, prerelease_rules, v_prefix_stripped, malformed_returns_false).

## v0.4.32-alpha — SHIPPED 2026-05-26 — updater migration: Velopack → tauri-plugin-updater

> Live in `Blazzer10200/rift-releases` since 2026-05-26T17:45Z (all assets present, `latest.json` actively polled). The "no latest.json published yet" note below was true at code-complete; superseded by the actual ship.

**One-time apply-phase wait on this update.** v0.4.31 ships with the broken Velopack apply path (`apply_updates_and_restart` spawns Update.exe and returns without exiting Tauri, so Update.exe sits idle waiting for the running pid to die). Expect 5-10 min on "Applying…". If it exceeds 15 min, force-quit Rift from Task Manager — Update.exe will finish the swap and relaunch automatically. **This will not happen again** — v0.4.32+ uses Tauri's first-party updater, which exits the app natively before NSIS swaps the binary. As an escape hatch, the Tauri-built `Rift_0.4.32-alpha_x64-setup.exe` is uploaded alongside the Velopack assets on the GitHub release; download + run it directly if auto-update misbehaves.
