## 1. What I changed (done this session)

**The problem, proven live.** While a turn streams, the live output-token count was rendered in
**three** places at once, and elapsed time in **two**:

| Indicator | Where | Showed | Window |
|---|---|---|---|
| `stage-strip` | top of assistant bubble | label + **tokens** | before first block (~1–15s) |
| `trailing-activity` | bottom of assistant bubble | label + **tokens** | during text streaming |
| `LivePills` | **composer toolbar** | elapsed + **tokens** + agents/shells/tools | whole turn |
| `heartbeat` | bubble turn-head | elapsed | whole turn |

Captured live mid-turn — the exact duplication you circled:
- in-bubble: `Conjuring… · 755 tokens`
- composer:  `0:22 · 755 tokens`  ← same number, two places, eyes have to travel up to read the label.

**The fix — one readout, by the prompt.** The descriptive label ("Conjuring…", "Reading X",
"Running cargo check") now rides the **composer LivePills** alongside elapsed + tokens, so the
whole live readout sits where you type. The in-bubble strips were de-duplicated:

- `LivePills.svelte` — added the whim-cycled activity label as the lead of the turn pill →
  composer now reads **`● Conjuring… · 0:22 · 755 tokens · ◍2 agents`**.
- `MessageBubble.svelte` `stage-strip` — reduced to a quiet **dots-only** pulse (no label, no
  tokens). The empty bubble still shows "a reply is forming here" without repeating the words.
- `MessageBubble.svelte` `trailing-activity` — **removed entirely** (markup + CSS). The tail
  block already pulses on the rail, and the label/tokens now live at the composer.
- Cleaned up the now-dead `stageLabel` / `liveTokenLabel` / `tailIsPending` /
  `showTrailingActivity` derives, the `WHIM_WORDS` cycler, the `fmtTokens` import, and ~70 lines
  of orphaned CSS in MessageBubble.

**Net:** token count 3→1, elapsed 2→1, label moved from the bubble down to the prompt. Less
duplication, less eye travel — exactly the ask.

**Verification (live, this session):**
- `npm run check` → **0 errors / 0 warnings** across 4093 files.
- CDP DOM poll across a real streaming turn:
  `Thinking… → Sussing… → Spelunking… · 0:05 · 109 tokens` in `.live-pills`;
  `.stage-strip` text empty (dots only); `.trailing-activity` absent. Behaved exactly as designed.

**Files touched:** `src/lib/components/assistant/composer/LivePills.svelte`,
`src/lib/components/assistant/MessageBubble.svelte`. Frontend-only, HMR'd live. No version bump.

## 2. Full run-through — per-workspace notes

### Home — strong, but the right column dies halfway
Polished bento: hero greeting + "New chat", a big "Ask Claude about rift-tauri…" launcher, a
Workspace card (folder + recents), "Jump back in" (6 convos), the Overview/Models stats
dashboard (KPI tiles + 18-week heatmap + fun-fact), and a "Plan limits" card.
- **Right column void.** "Plan limits" is one short card; the entire right column **below it is
  empty** down to the fold — the page reads lopsided (tall center, dead right).
- **Two "start a chat" affordances** stacked: the hero **"New chat"** button and the full-width
  **"Ask Claude…"** launcher do the same thing, inches apart.

### Chat — clean; the change landed here
Tab bar (tabs + workspace-root pill + branch chip + context pill + Panels menu), message
timeline, right-edge **Sub-agents** dock, composer. The status readout now consolidates at the
composer (see §1). Sub-agent dock empty-state ("No sub-agents yet") is nicely done.

### Local LLM — two toggles for one thing + a divergent header
Functional, complete page. But:
- **Duplicate master switch.** The header shows an **"Off" pill** *and* the Mode card shows a
  **"Local LLM mode" switch** — two controls for the same boolean, both visible at once. Pick one
  (recommend: header pill is the status indicator, the card switch is the control — or merge).
- **Header pattern matches Settings** (eyebrow + icon + title + desc) — good — but **Home uses a
  different hero**, so the three "top of page" treatments aren't a family yet.
- Big empty lower half (cards only fill the top third).

### Settings — the most consistent surface
Sticky hero + sub-tabs (Appearance · Accessibility · Assistant ● · Speech · About) over a
single readable column. Accent swatches, density, code preview, keyboard shortcuts. Clean.
- The **"0.10.0 · reinstall needed"** red chip is the expected one-time Velopack reinstall notice.
- The settings **gear** uses the same active-highlight as nav items, so when open it reads like an
  active tab even though it's pinned separately (minor).

## 3. Improvement backlog (prioritized, mapped, awaiting greenlight)

### P0 — consistency wins, low risk, high "feels intentional" payoff

1. **De-dupe the Local LLM master toggle.** Two switches for one state. → `LocalLlmPage.svelte`
   header `.sb-chip` vs Mode card `.st-switch`. Make the header chip *status only* (non-interactive)
   or drop the card switch. *(your "less duplicated" instinct applies here too)*

2. **Unify the page-header pattern into one component.** `SettingsPage.svelte` and
   `LocalLlmPage.svelte` **copy-paste the entire hero chrome** (`.sb-topbar/.sb-hero/.sb-eyebrow/
   .sb-chip/.sb-scroll/.sb-wrap/.st-block/.st-card/.st-switch/.st-input/.st-btn` …) as two separate
   scoped-CSS blocks — `LocalLlmPage.svelte:226` literally comments "Chrome replicated from
   SettingsPage." Every tweak must be done twice and they've already drifted (`.sb-wrap` is
   820px in Settings, **880px** in Local LLM). → extract a shared `PageHero.svelte` +
   `settings-chrome.css` (or shared `st-*` classes). Biggest consistency risk in the app.

3. **CLI-update is surfaced 3 different ways.** Home banner (`.dash-cli`), ChatTabsBar pill +
   popover (`.cli-badge`), Settings inline button — three visual treatments, and dismissing in one
   doesn't quiet the others. → one shared `UpdateNotice` treatment + a single dismiss state.

### P1 — layout balance & navigation clarity

4. **Fill the Home right column.** Below "Plan limits" add a second card (e.g. compact recent
   activity / streak sparkline / quick links) **or** widen the center and let "Plan limits" sit
   inline. Right now it's a tall void. → `HomePage.svelte` `.bento` grid `t-side`.

5. **Collapse the two Home "start chat" affordances** into one — keep the launcher input as the
   primary, demote or drop the hero "New chat" button (or make it "＋ New tab" semantics).

6. **Mark "Local LLM" experimental in the nav,** not just on the page. The page eyebrow says
   "Experimental" but the top-nav item is indistinguishable from Home/Chat. → small dot/badge on
   the `.navitem` (mirror the settings `.upd-dot`).

7. **Ctrl+3 → Settings, but Settings isn't in the nav row.** It's pinned as a gear (kbd 3) while
   Local LLM (kbd 4) *is* in the row — pressing Ctrl+3 jumps to a workspace with no visible nav
   item. → either show Settings in the row or document the gear's shortcut on hover.

### P2 — polish, tokens, a11y

8. **No shared size tokens across surfaces.** Tab height 36px, tab-item 26px, settings sub-tab
   42px, Home buttons 38px — each area hardcodes its own. → introduce `--control-h` / `--tab-h`
   for vertical rhythm.

9. **Bento `.sb-bento` means two different things** — column in Settings, 2-col grid in Local
   LLM, same class name. Rename one so a future third page doesn't inherit the wrong layout.

10. **Semantic/a11y nits:** `HomeStats` is a `<section>` while sibling tiles are `<div>`;
    "Plan limits" empty-state ("Checking plan limits…") has no timeout fallback; consider a single
    `aria-live` owner for the new composer label (done — it's on `.lp-label`).

11. **Color-token nits** already catalogued in `docs/ISSUES.md #39` (≈10 hardcoded colors that
    should be `--fg-*` / accent tokens) — fold into the same pass.

## 4. Animation & polish posture (rich, not overdone)

The app's motion language is already good and restrained — keep it as the bar:
- **Keep:** the model-tinted pulsing live dot, the whim-label crossfade (now at the composer),
  the staggered workspace-rise on entry, the heatmap, slim-scrollbar wells, tool-group slide.
- **Don't add:** entrance animations on static settings rows, bouncing icons, or anything that
  competes with the streaming text. The streaming text growing **is** the primary motion.
- **One consistency lever:** standardize transition timing on the existing `--ease-*` / duration
  tokens everywhere (a few components hardcode `200ms ease-out` inline). Same easing across
  surfaces = "designed by one hand," which is the quality signal you're after.
