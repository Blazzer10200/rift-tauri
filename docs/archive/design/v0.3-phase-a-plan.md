# v0.3 — Phase A Implementation Plan

> **Author:** 2026-05-17. Concrete execution plan for Phase A of the v0.3 UI redesign. See [v0.3-ui-redesign.md](v0.3-ui-redesign.md) for the design brief, [v0.3-brainstorm.md](v0.3-brainstorm.md) for feature options. This doc is execution-shaped; read it after the brief.

## Outcome

After Phase A, launching Rift opens directly into the Assistant chat as the main column with an empty dock on the right (stub panel headers, "coming in Phase B" bodies). User can:

1. Click any rail icon to toggle that panel open/closed.
2. Drag dock left-edge to resize between 280–560px.
3. Drag a panel header to reorder the dock stack.
4. Open Settings via `⌘,` / Titlebar gear / `cmdK` — slides over from the right; chat dims behind.
5. Use `Ctrl+1..8` to toggle panels by index.
6. Use the existing maximized-window 8px inset compensation, density toggle, server picker, command palette, terminal toggle (`Ctrl+\``) — **all unchanged**.

**Nothing works inside the panels yet.** Sync still functions in the background (engine never touched). Files / Conflicts / Activity / Diagnostics are reachable only via cmdK during Phase A — those migrations land in Phase B.

**Rollout gate:** behind `useV03Shell` ui-pref flag, default OFF until verified. AppShell branches: false → existing tab system; true → new shell. Lets us ship Phase A to main without flipping all users.

### [`TabRail.svelte`](../../src/lib/components/shell/TabRail.svelte)

**Button targets repurpose.** Same component, different mode under a prop:

```ts
let { mode = "tabs", active, onChange, onPanelToggle }: {
  mode?: "tabs" | "panels";
  active?: Tab;
  onChange?: (t: Tab) => void;
  onPanelToggle?: (id: PanelId) => void;
} = $props();
```

Under `mode="panels"`:
- Buttons map to panel IDs, not tab IDs.
- `data-active` reflects `uiPrefs.panels[id].open`.
- Groups reorganize: workspace (Files, Sync) · ai (Agents) · workspace (Tasks, Attachments, History) · status (Activity).
- Settings button (footer) opens slide-over modal instead of switching tabs.
- Hover-expand + pin behavior unchanged.
- Brand wordmark unchanged.

**Why a mode prop, not a fork:** TabRail is 406 lines, mostly CSS. The chrome (rail panel, indicator, hover-expand, pin) is identical between modes. Forking would duplicate ~350 lines of CSS.

## Risk + rollback (Phase A specific)

| Risk | Mitigation |
|---|---|
| `useV03Shell` flag accidentally on in prod build | Default false; toggle hidden behind "Experimental" header in Settings; restart required |
| TabRail mode prop breaks v0.2 rail behavior | Default mode `"tabs"` preserves existing call site; v0.3 explicitly passes `"panels"` |
| Settings slide-over animation jank on slow machines | 180ms is conservative; existing dialog-in is 140ms and works fine |
| Dock CSS grid breaks min-width on narrow windows | `data-dock-collapsed="true"` collapses to 0 below 880px; rail + main still get 528px min |
| Drag-reorder accessibility | Up/Down arrows on focused panel header reorder; documented in `cmdK` |
| localStorage corruption between v0.2 and v0.3 | Different keys (`rift.ui.panels.v1` is new; existing density/rail keys untouched). User can wipe just the v0.3 keys to reset. |

**Rollback boundary:** Phase A merges only when flag-OFF renders identical to today. Branch: `feat/v0.3-shell-phase-a`.
