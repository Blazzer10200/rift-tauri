# v0.4 — Chat Tabs + Split Dock

> **Author:** 2026-05-17, S76 planning. Concrete spec for the v0.4 era. Every fork is decided; the executing session transcribes, does not re-decide. Build on the v0.3 shell (flag-gated under `uiPrefs.useV03Shell`). v0.2 path stays untouched throughout — the toggle remains the rollback.

## The two features

1. **Chat tabs at the top of Rift** — browser-style tab row above the body, each tab = one Claude conversation. Open many, switch instantly, close keeps in History.
2. **Split right dock** — the existing dock can grow up to half-screen, and inside it splits horizontally into LEFT + RIGHT slots, each carrying its own panel stack. Example user goal: Tasks pinned to dock-left, Files pinned to dock-right, both visible at once.

Both ride the v0.3 toggle. Flag-off path renders pixel-identical to v0.2.

## Phase 1 — Chat tabs

### Where the tab strip lives

A dedicated 34px row inside `.middle` between the wire-error banner and `.body`, **only when `useV03Shell` is on**. Full width. Sits directly below the 44px Titlebar so visually it reads as the second header row — same pattern as Chrome / VS Code's editor tabs.

```
┌───────────────────────────────────────────────────┐  44px  Titlebar
├───────────────────────────────────────────────────┤  34px  ChatTabsBar
│ [Tab A]·[Tab B]·[Tab C]· …                    [+] │
├───────────────────────────────────────────────────┤
│ [body — main column + dock]                       │  1fr
├───────────────────────────────────────────────────┤  22px  StatusBar
```

### Tab anatomy

```
┌─────────────────────────┐
│ 💬 Tab title         × │
└─────────────────────────┘
   ↑ icon  ↑ truncated text  ↑ close (hover for inactive, always for active)
```

- **Icon:** `MessageSquare` (lucide). Replaced by a small pulsing accent dot while that convo is mid-stream.
- **Title source:** first user message truncated to 40 chars; falls back to "New chat" if empty.
- **Width:** flex `min: 120, max: 220`, shrinking to fit.
- **Active styling:** `bg-elev-1` (matches dock), no bottom-border, slightly bolder title.
- **Inactive:** `bg`, muted title, 1px `var(--border)` bottom-border, hover = `surface-hover`.
- **Close button:** only renders on hover for inactive tabs; always renders on active. `e.stopPropagation()` on close so clicking it doesn't switch to the tab.

### State model

Extend `AssistantStore`:

```ts
openTabs = $state<string[]>([]);          // ordered convo ids visible as tabs
// activeTabId is the existing `currentConvoId` — same slot, renamed semantically.
```

Helpers added to the store:

| Method | Behavior |
|---|---|
| `openTab(convoId)` | Push to `openTabs` if not present; set `currentConvoId = convoId`; load messages. |
| `closeTab(convoId)` | Remove from `openTabs`. If active, switch to next neighbor (right-priority). If `openTabs` becomes empty, set `currentConvoId = null` → empty state. |
| `newTab()` | Generate a new convoId, push to `openTabs`, set active, clear messages, prep first-turn. |
| `reorderTabs(fromIdx, toIdx)` | Splice reorder; persist. |
| `cycleTab(direction)` | +1 or -1 wrap-around through `openTabs`. |

Persist `openTabs` to `localStorage["rift.ui.tabs.v1"] = JSON.stringify({ openTabs, activeTabId })`. On `init()`:
1. Load history meta (`assistant_list_conversations` already does this).
2. Read stored `openTabs`; filter against existing convo ids (drop missing).
3. If `activeTabId` valid → load that convo. If not but `openTabs` has any → activate first. If none → set `currentConvoId = null`.

### Concurrent streams (decision: deferred to v0.4.1)

MVP keeps the singleton stream. Switching tabs mid-stream:
1. The streaming backend keeps writing to its convo's disk file (`appendMessage` persistence already handles this).
2. The visible chat in the new tab is whatever's on disk for that convo.
3. The streaming dot stays lit on the originating tab.
4. When the user switches back, `loadConversation` re-reads from disk and the chat catches up.

True concurrent live-streaming UI ("watch tab A stream while typing in tab B") is a follow-up. The data model already supports it via `--session-id`; the UI rendering needs per-convo message buffers, not the singleton `messages` $state. Not in scope for v0.4 phase 1.

### Right-click menu

Items, in order: **Close** · **Close others** · **Close to the right** · **Duplicate** (new tab w/ same convo workspace + cleared messages) · **Rename**. Rename = inline title edit; persists to the convo's stored `title` field.

### Keyboard

| Combo | Action |
|---|---|
| `Ctrl+T` | New tab. |
| `Ctrl+W` | Close active tab. |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | Cycle next/prev tab. |
| `Alt+1` … `Alt+9` | Jump to tab N. **NEW namespace** — leaves `Ctrl+1..8` free for dock panel toggles + `Ctrl+Shift+1..8` for accordion bypass. |

### Drag-to-reorder

HTML5 DnD on the tab element. Same pattern as `PanelShell` (`draggable`, ondragstart/over/drop). Tail-drop zone after the last tab for "drop here = append."

### Empty state (no tabs)

When `openTabs.length === 0`, replace the chat body with a centered card:

```
        ✨
   Start a new chat
   ┌──────────────┐
   │ + New chat   │
   └──────────────┘
   or pick one from History
```

Composer hides. The "+ New chat" button calls `newTab()`. "History" is the dock's History panel — clickable hint that expands it if collapsed.

## Phase 2 — Split dock

### Outer width

`DOCK_WIDTH_MIN` 260 (unchanged). `DOCK_WIDTH_MAX` recomputed at clamp time to `Math.min(900, window.innerWidth - 480)`. Reserves a 480px chat minimum. Cap of 900 prevents silly widths on ultrawide monitors. Effective: a 1920px monitor caps the dock at ~900; a 1366px laptop caps at ~880; a 2560px ultrawide caps at 900. Default stays 320.

Resize handle gets a **double-click action**: snap to ~50% viewport (`window.innerWidth / 2`, clamped to MAX). Gives the user a one-click "50/50" without needing to drag precisely.

### Internal split

`PanelState` grows a `slot: "left" | "right"` field. Default `"left"`. localStorage migration on load: any panel without `slot` becomes `"left"`. Existing users see no change.

Dock internal layout:

```css
.dock-body {
  display: grid;
  grid-template-columns: var(--dock-split-l, 1fr) 4px var(--dock-split-r, 0);
  /* When all panels are slot=left, --dock-split-r is 0 → right slot + handle collapsed. */
}
```

Variables driven from new state:

| Var | Source | Default |
|---|---|---|
| `--dock-split-l` | `uiPrefs.dockSplitPct` | `50%` when right slot occupied; `1fr` (100%) when only left has panels |
| `--dock-split-r` | derived from above | `(100 - dockSplitPct)%`, or `0` if no panels in right slot |

When `right slot` becomes empty (last panel dragged out OR closed-via-menu's new "Move to Left"), `--dock-split-r` collapses to 0 — the split handle disappears and left slot takes the full dock width.

When the user drags a panel into the right slot, `--dock-split-r` switches to `50%` default; the user can drag the new internal handle to adjust.

### Drag-to-cross-slot

While dragging a panel header:
1. Both slot bodies show a faint outline + label "Drop here" — colored hint that the slot is a target.
2. Drop on opposite slot = update `slot` field + insert at end of that slot's order.
3. Drop within same slot = reorder (current behavior).

Existing tail-drop zone exists per slot.

### Per-slot accordion

Accordion sweep (`applyOpenState(closeOthers: true)`) restricts to the dragged panel's slot. Opening a left-slot panel collapses other left-slot panels but doesn't touch right slot.

### Internal resize handle

Same 10px-wide RAF-throttled pattern as the outer handle, placed in the 4px middle grid column. Persistence: `localStorage["rift.ui.dock-split.v1"] = pct`. Min 20%, max 80% — prevents a sliver that's unusable.

### Keyboard for slot

No new keybinds. `Ctrl+1..8` still toggles the named panel (it expands wherever that panel lives — left or right slot). Drag is the only way to move slots.

## Decided forks (don't re-litigate)

| Question | Decision | Why |
|---|---|---|
| Tab strip location | Below Titlebar, full width, 34px | Browser/Cursor convention; doesn't fight Titlebar elements |
| Close = delete? | Close keeps in History | Matches VS Code; convos are precious |
| Concurrent streams | MVP single, true concurrent v0.4.1 | Real refactor; not blocking |
| Per-tab workspace | Yes, each convo carries its workspace | Already in convo metadata |
| Split mode toggle | Always-on, auto-collapses when right empty | Less UI for the toggle, drag is the affordance |
| Tabs vs split priority | Tabs first (Phase 1), then split (Phase 2) | Tabs are higher-impact daily-driver feature |
| New keybind namespace | `Alt+1..9` for tabs | Leaves `Ctrl+1..8` for panels |
| Settings entry | Slide-over (existing v0.3 pattern) | Don't break the modal flow |
| v0.2 path | Untouched throughout | Toggle remains the rollback |
