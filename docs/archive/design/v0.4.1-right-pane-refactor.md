# v0.4.1 — Right-pane refactor (drop the dock)

> **Author:** 2026-05-17, S77 follow-up planning. After v0.4.0-alpha shipped, daily-driver use surfaced two model mismatches with what the user actually wanted. This doc course-corrects. Every fork is decided; the executing session transcribes.

## The two model mismatches

1. **Tasks was Assistant-property, not a dock peer.** Tasks shows the multi-step plans Claude generates during a turn. It belongs inside Assistant, not stacked with Files / Sync / Activity. v0.3 swept it into the dock alongside everything else; that was wrong.
2. **The right side should be ONE full page at a time, not an accordion of summaries.** The user's mental model: "Assistant on the left. Open another full tool on the right, multitask." The dock-accordion model (8 panels, compact summary cards, maximize-to-center to view properly) inverted this — it pretended panels were small things and bolted on a maximize escape hatch. The correct shape is the reverse: each "panel" is a full-page surface that lives in a right pane, and you pick one at a time.

## What this collapses

Dropping the dock as a stacked-accordion primitive simplifies several things that fought each other:

| Before (v0.4.0) | After (v0.4.1) |
|---|---|
| Dock = N stacked panels w/ accordion | Right pane = ONE full page; activity bar picks which |
| Files / Sync render compact summary cards in dock | Files / Sync render their full surfaces in the right pane |
| `⛶` Maximize-to-center swaps panel into chat column | Gone. Right pane IS the full-surface view. |
| Esc restores chat from maximized | Gone. Chat is always on the left. |
| `PanelState.slot: "left" \| "right"` (intra-dock split) | Gone. One pane, no inner split. |
| `dockSplitPct` + internal vertical handle | Gone. Only the outer pane split remains. |
| `applyOpenState` accordion sweep | Gone. One page at a time is naturally exclusive. |
| Per-panel `getCount` / `getTone` count pips | Kept as small badges on the activity bar icons. |
| Tasks panel in registry | Removed. TasksDock stays inlined inside AssistantPage. |

## Decisions locked

| Aspect | Choice |
|---|---|
| Where Tasks lives | Inside AssistantPage (left pane), as in v0.2 + v0.3 internally. Never a dock peer. |
| Right-pane surface count | One at a time |
| Page switcher chrome | Vertical 40px activity bar on far right edge (VS Code pattern) |
| Activity bar icons | Files · Sync · Activity · Terminal · Agents · Attachments · History — 7 entries |
| Activity bar position | Always visible under v0.4.1 shell |
| Right pane default state | Closed (chat takes full width). Open by clicking an activity-bar icon. |
| Click active icon | Closes the right pane (toggle behavior) |
| Right pane width | Resizable via the existing outer horizontal handle. Range 320–1200, default 560. Dblclick → 50/50 of viewport. |
| Empty-state for right pane | Faint "Pick a tool from the activity bar →" placeholder + the bar itself |
| Maximize-to-center | Removed |
| `Esc` semantics | Closes Settings slide-over only (no more "restore from maximize") |
| `Ctrl+1..7` | Toggle activity-bar pages (replaces `Ctrl+1..8` for dock panels) |
| `Ctrl+0` | Close right pane (= focus chat) |
| History panel | Stays as a right-pane surface AND remains accessible via the existing `HistoryDrawer` in left pane for in-chat browsing |
| Drag-to-reorder activity bar | Yes — same HTML5 DnD pattern. Persists `rift.ui.activitybar-order.v1` |
| v0.2 path | Untouched |

### Grid spec

```css
.body[data-v04-1="true"] {
  grid-template-columns: minmax(0, 1fr) var(--right-pane-w, 0) 40px;
  /* var(--right-pane-w) = 0 when right pane closed; the activity bar (40px)
     is always visible. Outer resize handle straddles the gap btw left and
     right when the pane is open. */
}
```

When the right pane is closed (no surface picked), `--right-pane-w = 0` and the chat takes everything except the 40px activity bar.

## Components — new + retired

### New

- `src/lib/components/shell/ActivityBar.svelte` — vertical 40px icon strip on the far right edge. Renders the 7 page entries from a registry. Click toggles right-pane content. Active icon highlighted. Count badges (from existing `getCount` lambdas) overlay each icon when nonzero.
- `src/lib/components/shell/RightPane.svelte` — the slot host that renders the currently-selected page component full-width. Lazy-mounts each page on first open; keeps mounted thereafter so internal state survives toggles. Same `everOpened` latch PanelShell uses today.
- `src/lib/state/right-pane.svelte.ts` — `class RightPane { activeId: ActivityBarId | null; ... }`. Persists active id to `rift.ui.right-pane.v1`. `setActive(id)` / `toggle(id)` / `close()`.

### Retired

- `src/lib/components/dock/Dock.svelte` — delete.
- `src/lib/components/dock/PanelShell.svelte` — delete.
- `src/lib/components/dock/PresetPicker.svelte` — delete (preset choice is gone; there's only one chrome).
- `src/lib/components/dock/panels/TasksPanel.svelte` — delete (Tasks not a registry entry).
- Per-panel summary cards in `SyncPage.svelte` (`.sync-summary` block + `isDockSummary` branch) — delete. Sync renders its full page in the right pane, no compact mode needed.
- Per-panel summary card in `FilesPanel.svelte` — delete. Files becomes a thin wrapper around `<TwoPane />` rendered full-pane.

### Migrated

- `src/lib/components/dock/panels/*.svelte` → `src/lib/components/right-pane/*.svelte`. Most are already thin wrappers around the real surface — the move is mostly a rename + drop the `title`/`icon` prop contract (no longer needed; the activity bar carries that metadata).
- `src/lib/state/panel-types.ts` → `src/lib/state/activitybar-types.ts`. `PanelId` becomes `ActivityBarId` w/ `tasks` removed. `PanelState` is gone — replaced by `RightPaneState`.

## State refactor

`ui-prefs.svelte.ts` shrinks:

| Field | Disposition |
|---|---|
| `panels` | DROP — replaced by `rightPane` |
| `dockWidth` | RENAME → `rightPaneWidth`. Range 320–1200, default 560. |
| `dockSplitPct` | DROP |
| `maximized` | DROP |
| `presetPicked` | DROP |
| `dockAccordion` | DROP |
| `useV03Shell` | KEEP — but the toggle label updates to "Experimental v0.4 shell layout." Flag-off path is still v0.2. |
| (new) `rightPane.activeId` | `ActivityBarId \| null` |
| (new) `activityBarOrder` | `ActivityBarId[]` — user-reorderable icon order |

Storage key migration on load:
- Read legacy `rift.ui.panels.v1` ONCE on first v0.4.1 launch. If it exists, look at which panel had `open: true` most recently; if exactly one, seed `rightPane.activeId` w/ that id (drop `tasks` if it surfaces). Then delete the legacy key.
- Read legacy `rift.ui.dock-w.v1` → rename storage to `rift.ui.right-pane-w.v1`, clamp into new range.
- Delete `rift.ui.dock-split.v1`, `rift.ui.maximized.v1`, `rift.ui.preset-picked.v1`, `rift.ui.dock-accordion.v1` on first launch.

## Phases

1. **Phase 1 — Tasks back to Assistant.** Drop `tasks` from registry, delete `TasksPanel.svelte`, verify TasksDock still renders inside AssistantPage unaffected. Easy 30-min win; ship as v0.4.0-alpha hotfix OR as the first commit of v0.4.1.
2. **Phase 2 — Activity bar + RightPane state.** New components + state file + storage migration. Mount under v0.3 toggle (same toggle, new shell branch). Wire activity-bar click → set/clear `rightPane.activeId`.
3. **Phase 3 — Retire dock primitive.** Delete Dock.svelte / PanelShell.svelte / PresetPicker.svelte / TasksPanel.svelte / FilesPanel.svelte's summary card / SyncPage.svelte's summary card branch. Update AppShell body grid. Drop `maximized` / `dockSplitPct` / accordion code from ui-prefs.
4. **Phase 4 — Polish + ship.** Update Settings → Appearance → Layout sub-section (drop "Reset split / Close all tabs" → keep "Close all tabs" only, add "Reset right pane" button). Three-file version bump `0.4.0-alpha` → `0.4.1-alpha`. CHANGELOG entry. CDP smoke `smoke-v04-1.sh`. Archive v0.4 design doc.

## Don't-touch

- `useV03Shell` toggle name stays (it's an established storage key; relabel is fine but don't break upgrade). v0.2 path untouched throughout.
- ChatTabsBar from v0.4 unchanged. Tabs live above the body.
- AssistantStore + chat tab plumbing unchanged.
- All v0.4 keybinds for chat tabs unchanged.
- Three-file version lockstep.
- Self-replace dance for builds.

## Open future-considerations (NOT in v0.4.1)

- **Multiple right-pane stacking** — pinning two pages in a vertical stack on the right (e.g. Sync top, Terminal bottom). User explicitly didn't ask for this; the new model is one-page-at-a-time. Revisit if multi-tasking demand surfaces.
- **Floating windows** — detach a right-pane page into its own Tauri window. v0.5+ territory.
- **Per-tab right-pane state** — each chat tab remembers what was open on the right. Possible v0.4.2 polish.
