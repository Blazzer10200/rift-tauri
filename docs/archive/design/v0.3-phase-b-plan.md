# v0.3 — Phase B Migration Matrix

> **Author:** 2026-05-17 (parent session, while Phase A is mid-CDP-verification). Execution plan for the 5 surface migrations that turn the empty Phase-A dock into a fully-functional v0.3 shell. Read [v0.3-phase-a-plan.md](v0.3-phase-a-plan.md) first; this doc assumes the panel primitive + ui-prefs surface from Phase A.

## Outcome

After Phase B, every dock panel renders the real existing functionality wrapped in `PanelShell`. The `useV03Shell` flag flipped ON becomes the new daily-driver experience: chat-center + working dock + slide-over Settings.

What's done:
- 8 panel stubs swapped for real components in `src/lib/components/dock/panels/index.ts`
- `TerminalPanel` drops its floating-overlay mode entirely under v0.3
- `ActivityFeed`, `SyncPage`, `TwoPane` shed their page-shell chrome (headers, toolbars that PanelShell now owns)
- `Conflicts` folded into Sync panel as expandable section — standalone tab dies under v0.3
- `TasksDock` + `HistoryDrawer` hoisted out of `AssistantPage` into top-level dock panels
- `assistant.ui.dockOpen` field deleted (replaced by `uiPrefs.panels.tasks.open`)

What's NOT done (deferred to Phase C):
- Maximize-to-center swap logic (panel-as-main); Phase B leaves the `⛶` button stub-clickable
- Drag-reorder polish, keyboard reorder, dock-width animation tuning
- Multi-user presence dots in StatusBar

## The 5 migrations

### Mig 1 — SyncPage → Sync panel (heaviest)

**Source:** [`src/lib/components/sync/SyncPage.svelte`](../../src/lib/components/sync/SyncPage.svelte) (1223 LOC). Owns the drift table, rescan/pull/push controls, Mirror mode UI.

**Side-effect:** [`src/lib/components/conflicts/ConflictsPage.svelte`](../../src/lib/components/conflicts/ConflictsPage.svelte) folds in as an expandable section. The standalone "Conflicts" panel dies; conflict count badges on the Sync panel header.

**What changes in the source file:**
- Strip its own page-level `<header class="page-head">` (or equivalent) — PanelShell owns the header now. Title becomes `Sync`. Subtitle (server name) might lift into PanelShell via a slot or get inlined as a body row.
- Trim outer padding (PanelShell wraps in its own body padding).
- Keep all internal logic: rescan, pull/push, drift table, Mirror mode confirms, ConflictsPage inline.

**Files this touches:**
- `src/lib/components/sync/SyncPage.svelte` — chrome trim, internal Conflicts mount
- `src/lib/components/dock/panels/SyncPanel.svelte` (new) — thin wrapper, ~30 LOC: `<PanelShell><SyncPage /></PanelShell>`
- `src/lib/components/dock/panels/index.ts` — swap `SyncStub` → `SyncPanel`
- Delete `src/lib/components/dock/panels/SyncStub.svelte`

**Watch-out:** the auto-rescan timer in [`AppShell.svelte:79-93`](../../src/lib/components/AppShell.svelte#L79-L93) currently fires regardless of which tab is active. Under v0.3 it must still fire regardless of whether the Sync panel is open. Behavior unchanged; just verify no regression.

**Header badge:** wire `count={connection.conflictCount}` on the PanelShell to surface conflict count as a red pip on the panel header.

**Estimated LOC:** ~50 changed in SyncPage, ~30 new in SyncPanel wrapper, ~10 in index.ts. Net low.

### Mig 2 — TwoPane → Files panel

**Source:** [`src/lib/components/browser/TwoPane.svelte`](../../src/lib/components/browser/TwoPane.svelte). Hosts `LocalPane` + `RemotePane` side-by-side w/ `PathBreadcrumbs`.

**Width concern:** TwoPane is *wide* — two side-by-side file browsers. The default dock width (320px) is too narrow. Two resolutions:
- **(a)** Files panel auto-prompts maximize-to-center on open (good UX, but Phase C doesn't ship maximize yet)
- **(b)** Files panel stacks Local on top of Remote vertically when dock < 600px wide

Recommendation: **(b) for Phase B**, since maximize isn't real yet. Add a CSS media query inside TwoPane: `@container (max-width: 600px) { flex-direction: column; }`. Cheap fix; reverts to side-by-side once Phase C maximize ships + user maximizes.

**What changes:**
- Strip outer chrome (page-level title bar, toolbar buttons — keep functional buttons, drop page-shell padding)
- Add container query for vertical stacking
- Keep all browse logic, breadcrumbs, lock badges intact

**Files this touches:**
- `src/lib/components/browser/TwoPane.svelte` — chrome trim + container query
- `src/lib/components/dock/panels/FilesPanel.svelte` (new) — wrapper
- `src/lib/components/dock/panels/index.ts` — swap `FilesStub` → `FilesPanel`
- Delete `FilesStub.svelte`

**Estimated LOC:** ~40 changed in TwoPane, ~30 new in wrapper.

### Mig 3 — TerminalPanel → Terminal panel (drop overlay mode)

**Source:** [`src/lib/components/terminal/TerminalPanel.svelte`](../../src/lib/components/terminal/TerminalPanel.svelte) (818 LOC). Currently a floating bottom overlay that toggles via `terminal.toggle()`.

**Heaviest behavior change in Phase B.** The overlay-mode rendering, drag-to-resize-from-top, position-over-content logic — all of it is irrelevant under v0.3. The Terminal becomes a regular dock panel that renders its xterm shells inside PanelShell's body.

**What changes:**
- Branch on `uiPrefs.useV03Shell`: under v0.3 mode, render NO overlay chrome — just the tab bar + xterm + find bar. The PanelShell hosts it.
- `terminal.toggle()` should also gain v0.3 awareness: under v0.3 it calls `uiPrefs.togglePanel("terminal")` instead of flipping `terminal.open`.
- Keep `state/terminal.svelte.ts` exactly as-is — tab management, shell sessions, drop-file all preserved.

**Critical preservation:**
- Multi-tab state survives panel toggle (PanelShell uses `mounted` flag for keep-alive)
- xterm session don't disconnect on panel close

**Files this touches:**
- `src/lib/components/terminal/TerminalPanel.svelte` — major surgery: split rendering into v0.2 overlay path + v0.3 inline path
- `src/lib/components/dock/panels/TerminalPanel.svelte` (new) — wrapper, name collides w/ existing — use `dock/panels/TerminalDockPanel.svelte` instead
- `src/lib/state/terminal.svelte.ts` — `toggle()` becomes useV03-aware
- `src/lib/components/dock/panels/index.ts` — swap stub
- AppShell.svelte — keep the `terminal.toggle()` call w/in Ctrl+\` handler; the function itself becomes branch-aware
- Delete `TerminalStub.svelte`

**Estimated LOC:** ~150 changed in TerminalPanel, ~30 new wrapper, ~15 changed in terminal store. Heaviest of the 5 migrations.

### Mig 5 — TasksDock + HistoryDrawer hoisting

**Source:** Both are currently INSIDE `AssistantPage.svelte` (see [`AssistantPage.svelte:61-99`](../../src/lib/components/assistant/AssistantPage.svelte#L61-L99)). They render as inline columns next to the chat.

**Migration:** lift them OUT of AssistantPage into top-level dock panels. AssistantPage shrinks to just header + chat + composer (no inline drawer/dock).

**What changes:**
- `AssistantPage.svelte` — delete the `HistoryDrawer` + `TasksDock` mounts from `.layout`; delete the `.dock-slot` div; AssistantPage's `.layout` becomes just chat column
- `TasksDock.svelte` — strip its own header (PanelShell owns it now)
- `HistoryDrawer.svelte` — same
- `state/assistant.svelte.ts` — delete `ui.dockOpen` field + `toggleDock()` method (now governed by `uiPrefs.panels.tasks.open` + `uiPrefs.panels.history.open`)
- `state/assistant.svelte.ts` — anything that reads/writes `ui.dockOpen` (header pulse animation, etc.) gets updated to read `uiPrefs.panels.tasks.open`
- `AssistantHeader.svelte` — the pulse + chevron buttons that toggle the inline dock now call `uiPrefs.togglePanel("tasks")` / `uiPrefs.togglePanel("history")`
- `src/lib/components/dock/panels/TasksPanel.svelte` (new) — wrapper
- `src/lib/components/dock/panels/HistoryPanel.svelte` (new) — wrapper
- Swap both stubs in `index.ts`; delete `TasksStub.svelte` + `HistoryStub.svelte`

**Watch-out:** [`assistant.svelte.ts`](../../src/lib/state/assistant.svelte.ts) — any usage of `ui.tasksUpdatedAt` for the pulse animation in `AssistantHeader.svelte:36-46` stays exactly the same; only the dock-open visibility check changes data source.

**Estimated LOC:** ~30 changed in AssistantPage, ~40 changed in TasksDock+HistoryDrawer combined, ~20 changed in AssistantHeader, ~20 changed in assistant.svelte.ts, ~60 new in 2 wrappers.

## Parallelization — 3 sessions, 2 waves

Per `~/.claude/rules/agents.md` cap of 3 parallel. Migrations sized so each wave has roughly balanced workload (heaviest paired w/ lightest).

### Wave 1 (3 parallel)

| Session | Migration | Heft |
|---|---|---|
| α | Mig 1: SyncPage → Sync panel + Conflicts inline | heavy |
| β | Mig 3: TerminalPanel overlay → dock panel | heavy |
| γ | Mig 4: ActivityFeed → Activity panel | light |

### Wave 2 (2 parallel)

| Session | Migration | Heft |
|---|---|---|
| δ | Mig 2: TwoPane → Files panel + container query | medium |
| ε | Mig 5: TasksDock + HistoryDrawer hoist + assistant state surgery | medium |

**Why split:** Wave 1's α + β both touch substantial existing components but in different domains (sync vs terminal). γ is the easy ramp. Wave 2's δ + ε both have cross-file ripples (TwoPane CSS + AssistantPage internal restructure) — but again, different files.

**File-conflict guarantee:** every session's file scope is non-overlapping. No two sessions edit the same file.

## Verification per session

Each session ends by:
1. `npm run check` → 0 errors
2. Manual smoke check via CDP if they have the wrapper alive (optional — parent session will run full sweep after all 5 land)
3. Reports back: files touched, LOC, any spec ambiguities resolved, any places where the migration required touching a file outside their declared scope

After all 5 migrations land, parent session (me) runs the full Phase A CDP checklist + new Phase B specifics (flip every panel open, verify real content renders, multi-tab terminal survives toggle, etc.).

## Risks

| Risk | Mitigation |
|---|---|
| TerminalPanel overlay/inline branch is fragile | Mig β session uses an explicit `if (uiPrefs.useV03Shell) ... else ...` at the component level, not file-level — old behavior preserved when flag off |
| AssistantPage hoisting breaks the streaming-pacer + scroll-stick logic | Mig ε keeps the chat column + composer + scroll machinery untouched; only removes inline HistoryDrawer + TasksDock + `.dock-slot` div |
| `dock/panels/index.ts` merge conflicts | Each session's edit is one import line + one entry; trivial 3-way merge or hand-resolve at parent |
| TwoPane container query unsupported in WebView2 build | WebView2 supports container queries since the Chromium 105+ baseline; Rift ships on 122+ — safe |
| Conflict inline expansion bloats the SyncPanel header | Conflict badge stays in PanelShell header (just a count pip); expansion lives in body, not header |
